Semana 07: contratos compartidos y primer PR bien hecho

Se consolidó la capa de contratos transversales (_shared.yaml, api-gateway.yaml) y se corrigió el flujo de Pull Request a partir de la revisión del profesor.

01 Qué se entregó

_shared.yaml — v1.1.0

Schemas compartidos entre dominios

Se agregaron los objetos de valor que de verdad se repiten en 2+ servicios, en vez de dejar el archivo genérico.

UserRole DateRange Money CorrelationId (header) Conflict 409
api-gateway.yaml

Ruteo y roles alineados al dominio real

Los upstreams genéricos y los roles de ejemplo se reemplazaron por los servicios y roles reales del proyecto.

GUEST / HOST / ADMIN auth-service catalog-service booking-service payment-service

02 Lo nuevo: hacer un Pull Request bien

Nombrar el branch según el tipo de repo

feat/update-shared → docs/update-shared-schemas

Commit con Conventional Commits

docs(api): add UserRole, DateRange and Money to _shared.yaml

Descripción real del PR

Explicar el qué y el porqué — no dejarlo vacío.

Revisión del profesor

Detectó que un PR anterior tenía diff vacío (solo se quitó el salto de línea final) — el contenido nunca llegó al repo.

Corrección aplicada

Se re-abrió el PR con el contenido real, branch y commit corregidos.

aprendizaje clave

Un PR aprobado no significa "sin observaciones" — el profesor aprueba siempre y evalúa en la sustentación qué se hizo con cada hallazgo.
